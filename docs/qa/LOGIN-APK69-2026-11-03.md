# Android login investigation — candidate APK 69

## Report and evidence

The user reported the generic application error boundary after authentication
in APK 68 (version 1.6.7, source bed406a1df71a2a0ca01b080c011dc89c2c513e2).
Read-only backend checks confirmed successful email confirmation/sign-in and
an eligible trial whose registration had not yet been completed.

The retained render diagnostics start with `KeyboardAvoidingView`,
`RNCSafeAreaView`, `Screen`, and `TrialRegistrationBoundary`. The raw exception
message was intentionally not retained. No account, subscription, trial consent,
or customer workspace data was changed during this investigation.

## Verified navigation improvement

The trial and operational gates previously wrapped the application's Stack.
Loading, retry, and redirect states removed that navigator. In Expo Router SDK57
the separate internal `__root` navigator remains registered, so container
readiness alone is not a valid regression assertion.

With the application's Stack absent, the router targets a replacement of the
outer `__root` route. A controlled reproduction with the installed navigation
core and SDK57 action/path helpers confirmed an extra root/provider mount.
The destination can still be reached; an infinite redirect loop was not observed.

The gates now run in the Stack's `layout`. Its navigation state remains registered
while protected screen content and workspace effects remain gated. The same
reproduction targets the app's registration route and preserves the root/provider
instances. Operational deep links still redirect denied users to the paywall.

## Diagnostics and packaging

Client diagnostics add fixed failure categories, numeric build identity, and
separate JavaScript function names. Raw messages, arguments and URLs are not
exported. The complete standard error name/message header is removed before
parsing JavaScript frames; unsupported formats produce no JavaScript frames.
This also prevents multiline message text from being mistaken for a frame.

Android versionCode is 69, versionName remains 1.6.7. The release gate retains
the existing package, ARM64 requirement, and EAS production signing certificate.
No iOS artifact or public store release is part of this candidate build.

## Validation and limits

The revised navigation regressions include SDK57's outer navigator and derive
pathname from resulting navigation state. All five fail against APK68's layout
and pass with the candidate layout. They cover loading, retry, destination
reachability, provider lifetime, and denied operational deep links. Native drawing
and backend services are mocked; the tests do not reproduce the physical-device
exception shown in the screenshot.

Diagnostic regressions cover known/unknown categories, build identity, sensitive
arguments/URLs, multiline messages, unsupported stacks, and offline delivery.
Detailed final command results and APK identity/signature checks accompany the
delivered artifact separately.

This is a candidate fix for the reported incident, not proof that its exact native
crash is resolved. Confirmation requires repeating login/reload on the affected
phone or obtaining its native application log. A new failure in APK69 can be
distinguished by its build identity and classified diagnostic code.
